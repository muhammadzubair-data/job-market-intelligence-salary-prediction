# Model card — JobScope AI salary estimator

## Intended use
Portfolio demonstration of a reproducible salary-modelling workflow, and exploratory estimates on **user-supplied, normalised** job-posting data. It is **not** for setting pay, screening candidates or any automated decision about people.

## Model
- **Type:** best of {Ridge, Random Forest, Gradient Boosting, HistGradientBoosting}, chosen by 5-fold CV MAE. On the demo data the winner is **Gradient Boosting** (300 trees, learning rate 0.05, depth 3).
- **Target:** annual salary in USD, modelled as `log1p(salary)` and converted back.
- **Inputs:** job title, country, employment type, work arrangement (one-hot), years of experience, number of listed skills (scaled), canonical skills from NLP (multi-hot).
- **Not used:** description text, posting IDs, source and any personal attributes.

## Training data
The default is 750 synthetic postings (seed 42). Salary is generated by
`(role_base + 3,900·years) × country_factor × 1.04[remote] × U(0.82, 1.18)`. Skills are random and have no effect on salary.

## Evaluation (synthetic data — not real-world performance)
| Metric | Value |
|:--|--:|
| 5-fold CV MAE (train split) | $8,572 ± 740 |
| Holdout MAE / RMSE / R² | $9,105 / $12,065 / 0.924 |
| Median baseline holdout MAE | $37,960 |
| 80% interval coverage (holdout) | 82% |

The irreducible noise in the generator (±18% multiplicative) sets a floor on achievable error. Ridge performs about the same as Gradient Boosting because the generator is log-linear.

## Uncertainty
Split-conformal: the 80th-percentile (finite-sample adjusted) absolute out-of-fold residual on the log scale gives a multiplicative interval around each prediction. Coverage is guaranteed only on average and under exchangeability, so it won't hold under distribution shift (new countries, new time periods).

## Assumptions
1. Salaries are comparable: same currency (USD), annual, gross.
2. Rows are independent; no employer repeats many near-identical postings.
3. Future postings resemble the training sample.

## Limitations & risks
- A random split can overstate accuracy compared with time-based or employer-grouped validation.
- Rare roles and countries get noisy estimates (`min_frequency=3` groups very rare levels).
- What-if changes are model associations, not causal effects of acquiring a skill.
- Per-group errors differ (see **Model Performance → error by role/country**). Audit before any real use.

## Reproduce
```bash
python scripts/train.py            # prints CV + holdout tables, writes artifacts/
```
